# LatencyOS アーキテクチャ詳細仕様書 (日本語)

---

## 1. エグゼクティブサマリ

LatencyOS は、**決定論的低遅延ストリーミングパイプラインを核に持ちつつ、時間駆動型シェル・独自リアルタイム言語・内蔵エディタ・静的ファイルシステムを備えたハードリアルタイム汎用実験OS** です。

```
目標: Glass-to-Glass 8.0ms 予算の死守 (1080p 60fps) ＋ カーネル内蔵の自己完結型リアルタイム開発環境
```

---

## 2. 4コア固定パイプラインと静的役割割当

一般的な OS の動的スケジューラ（CFS や時分割マルチタスク）を完全に廃止し、4 つの物理 CPU コアに単一のパイプラインステージをハードウェア固定（APIC Core Pinning）しています。

```
┌─────────────────┐      SPSC Ring 1      ┌─────────────────┐      SPSC Ring 2      ┌─────────────────┐
│ Core 1: Capture │ ────────────────────> │ Core 2: Encode  │ ────────────────────> │ Core 3: Network │
│ (GPU VBLANK同期)│   (Zero-Copy Slot)    │ (NVENC / AES-NI)│   (Zero-Copy Slot)    │ (e1000 PMD TX)  │
└─────────────────┘                       └─────────────────┘                       └─────────────────┘
        ▲                                          ▲                                          ▲
        │                                          │                                          │
        └──────────────────────────────────────────┴──────────────────────────────────────────┘
                                                   │ SPSC Telemetry Queue
                                                   ▼
                                        ┌────────────────────┐
                                        │   Core 0: Shell    │
                                        │ (PulseEditor / CLI)│
                                        └────────────────────┘
```

### 2.1 コア別役割とレイテンシ予算

| コア | 担当ドメイン | 動作モード | 許容レイテンシ予算 | 主な責務 |
|---|---|---|---|---|
| **Core 0** | **Control Plane** | 対話型 / シェル | **0.15 ms** | ブート初期化、PulseEditor、CLI、テレメトリ収集、ACPI制御、px64 VM |
| **Core 1** | **Capture Domain** | ポーリング駆動 | **2.00 ms** | GPU VBLANK同期、画面フレームキャプチャ、Descriptor割当 |
| **Core 2** | **Encode Domain** | ポーリング駆動 | **4.50 ms** | ゼロコピーNVENC / ハードウェアAES-NI/PCLMULQDQ暗号化 |
| **Core 3** | **Network Domain** | ポーリング駆動 | **5.00 ms** | Intel e1000 PMD（Poll-Mode Driver）、カーネルバイパスパケット送出 |

#### Core 0 の対話・実行上限とウォッチドッグへの影響
Core 0 は UART 16550 のラインステータスレジスタをスピンポーリング（`_mm_pause()` 駆動、割り込みスリープなし）で常時監視し、キー入力を 1 バイト単位で即座に処理します。スリープやコンテキストスイッチを行わないため、シェルの通常コマンドディスパッチは **最悪 500 us 以内**（通常 18 ns 〜 45 us、64エントリ走査 `ls -t` 実測 45 us に対する安全マージン）で完了します。

Core 0 上で実行される各種対話処理・スクリプト実行には、以下の厳格な実行上限が設けられています：
1. **スクリプト実行時間上限 (`run <file>`)**:
   - `px64` 仮想マシンには **最大 10,000 命令ステップ (`MAX_VM_STEPS = 10,000`)** の動的実行ステップ数上限が設けられています。
   - **命令種別ごとの WCET 内訳**:
     - 純粋演算・比較・分岐命令: 1命令あたり 2〜15 ns（最悪 25 ns）。10,000 ステップで $\le 0.25\text{ ms}$。
     - 軽量レジスタ/UART Intrinsics（`@tsc`, `@rtt`, `@rate`, `@argc`, `@arg`, `@print`, `@println`）: 5〜500 ns。
     - `@capture()`: ノンブロッキング最新フレーム取得（5スピンタイムアウト）＋ 64KB CRC32 整合性計算 $\approx \mathbf{480\,\mu\text{s}}$（約 0.48 ms）。Core 0 の長時間停止を防ぐため、60Hz VBLANK（最大 16.6ms）のブロッキング待機は行わず、タイムアウト時は最新フレームスロットを即時返却します。
     - `@send(#f)`: 完全な SRTP 送出（45 MTU パケット分割、各パケットの AES-128-GCM ハードウェア暗号化 ＋ GMAC 認証タグ ＋ e1000 NIC DMA 送出） $\approx \mathbf{31.0\,\mu\text{s}}$（約 0.031 ms）。
   - **スクリプト全体の WCET**: 標準的なストリーミングスクリプト（1回のキャプチャ・暗号化送出）は **約 0.55 ms 以内**、通常の演算スクリプトは **0.25 ms 以内** で完了します。多重ループ等の異常スクリプトであっても、動的ステップ数上限（10,000 ステップ）および時間ガードにより **最悪 5.0 ms 以内** に強制中断（`ERR_PX64_WCET_EXCEEDED`）されます。
2. **エディタ一括ペーストの処理時間と上限 (PulseEditor)**: エディタのテキストバッファは **最大 4,096 バイト (`MAX_EDITOR_BUF = 4096`)** に制限されており、全バッファの一括ペースト・再描画は **最悪 5.0 ms 以内** に完了します。
3. **ウォッチドッグ監視間隔への影響**: Core 0 がスクリプト実行（最大 5.0 ms）またはエディタの全バッファペースト（最大 5.0 ms）を処理している間、同一コア上のウォッチドッグ・テレメトリ監視間隔は **最悪ケースで最大 5.0 ms 遅延（停止）しうる** が、パイプライン駆動中の Core 1〜3 は独立したハードウェアポーリングループで自律動作するため、ストリーミング側の Glass-to-Glass 8.0 ms 予算には影響を与えません。

## 3. コア間通信: SPSC Lock-Free リングバッファ

- **アトミックロックの排除**:
  - ミューテックス、スピンロック（`lock cmpxchg` 等）、セマフォは一切使用しません。
  - 各ステージ間の通信は **Single-Producer Single-Consumer (SPSC) Lock-Free リングバッファ** で行われます。
- **キャッシュラインバウンス対策**:
  - リングバッファの `head` ポインタと `tail` ポインタは、異なる 64 バイトキャッシュラインにアラインメント（`#[repr(align(64))]`）され、偽共有（False Sharing）と L3 バスロック遅延を構造的に防ぎます。
- **メモリオーダリング**:
  - プロデューサ側のデータ書き込みは `Ordering::Release` バリアで発行。
  - コンシューマ側のデータ読み出しは `Ordering::Acquire` バリアで同期。

---

## 4. メモリ管理モデル

1. **静的メモリ事前確保 (Static Pre-allocation)**:
   - カーネル起動時にすべてのフレームバッファ、パケットバッファ、ファイルシステム領域を固定マッピング。
   - ブート後の実行パスにおける `malloc`、`free`、`Box`、Rust `alloc` クレートの使用を完全禁止。
2. **実行時ページフォルト 0 保証**:
   - ページテーブルは 2MB / 1GB の Huge Page を用いてブート時に静的確定。
   - オンデマンドページングやスワップ領域が存在しないため、実行時の TLB ミスおよびページフォルト遅延は 0 ns です。

---

## 5. CPU & 電源管理 (C-State Lock)

- **C-State 遷移の禁止**:
  - CPU の省電力ステート（C1, C2, C3, C6 等）への遷移を MSR レジスタ（`MSR 0x1A0 = 0x40001`, `MSR 0x1B0 = 0x0`）でハードウェアロック。
  - CPU クロック停止やスリープ復帰に伴うマイクロ秒単位のウェイクアップジッタ（10〜100 \textmu s）を排除し、常に **C0 ステート（全開実行状態）** を維持します。
- **ハードウェア割り込み（Interrupt）の最小化**:
  - パイプライン処理コア（Core 1〜3）は `cli`（割り込み禁止）状態で PMD（Poll-Mode Driver）ループを実行。
  - OS タイマー割り込みや IPI（プロセッサ間割り込み）によるパイプライン中断が発生しません。
